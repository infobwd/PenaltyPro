## ก่อนแตะอะไรก็ตาม: สำรองก่อนเสมอ

**ห้ามข้ามขั้นนี้แม้แต่ครั้งเดียว** migration ในโปรเจกต์นี้เป็น `ALTER`/`CREATE` ตรง ๆ
รันซ้ำไม่ได้ และไม่มีสคริปต์ย้อนกลับ ทางกลับมีทางเดียวคือ restore

```
phpMyAdmin -> เลือกฐาน bwdacth_kickoff -> Export
  Method: Custom
  Format: SQL
  ✅ Add DROP TABLE / CREATE TABLE
  Compression: gzipped
  ตั้งชื่อไฟล์: kickoff-YYYYMMDD-HHMM.sql.gz
```

เก็บไว้นอกโฮสต์ด้วย (ดาวน์โหลดลงเครื่อง) — ถ้าโฮสต์มีปัญหา ไฟล์ที่อยู่บนโฮสต์ก็หายไปด้วย

ไฟล์ที่อัปโหลดของผู้ใช้ (`storage/uploads/`) ไม่ได้อยู่ในฐานข้อมูล
ต้องสำรองแยกด้วย File Manager -> Compress -> ดาวน์โหลด

## ขั้นตอนขึ้นระบบ

### 1. ฐานข้อมูล

รัน migration ที่ยังไม่ได้รัน **เรียงตามลำดับ** ผ่าน phpMyAdmin -> Import
รายการทั้งหมดอยู่ใน [../db/README.md](../db/README.md)

เช็กว่าครบไหมโดยไม่ต้องเปิดฐานข้อมูล:

```
https://kickoff.bwd.ac.th/api/?action=health
```

`col_*` และ `table_*` ต้อง `ok: true` ทุกตัว ถ้าตัวไหน false ในช่อง `detail` บอกไว้แล้ว
ว่าต้องรันไฟล์ไหน

### 2. ไฟล์ฝั่ง server

อัป `api/` ทั้งโฟลเดอร์ **ยกเว้น**:

| ห้ามอัป | เหตุผล |
|---|---|
| `api/config.local.php` | ชี้ฐานทดสอบในเครื่อง ถ้าไปทับบนโฮสต์ระบบจะต่อฐานผิด |
| `api/config.example.php` | เป็นแค่แม่แบบ |

`api/config.php` บนโฮสต์ **ห้ามทับ** — เป็นของจริงที่มีรหัสฐานข้อมูล
ถ้าเพิ่มคีย์ใหม่ใน `config.example.php` ให้ไปเพิ่มด้วยมือในไฟล์บนโฮสต์

`api/vendor/` (1,199 ไฟล์) อัปครั้งเดียวพอ ไม่ต้องอัปซ้ำทุกรอบถ้า `composer.lock` ไม่เปลี่ยน
โฮสต์ไม่มี composer จึง commit ลง git ไว้โดยตั้งใจ

### 3. ไฟล์ฝั่งหน้าเว็บ

```bash
npm ci
npx tsc --noEmit
npx vite build
```

อัปทุกอย่างใน `dist/` ไปที่ document root

`public/.htaccess` ถูกคัดลอกไป `dist/` ให้อัตโนมัติ — ต้องมีตัวนี้ ไม่งั้นเปิด
`/schedule` ตรง ๆ จะ 404 (SPA fallback)

### 4. ตรวจหลังขึ้น

```
?action=health   ->  ready: true
```

แล้วไล่มือตามนี้ (ลำดับเดียวกับ `tools/smoke-test.php` แต่ทำบนของจริง):

1. เปิดหน้าแรก — เห็นโลโก้และชื่อรายการถูกต้อง
2. `/school` เข้าด้วยรหัสโรงเรียนจริง 1 โรงเรียน — เห็นทีมของตัวเอง
3. แอดมินอนุมัติทีมนั้น + ยืนยันสลิปค่าสมัคร
4. **กลับไป `/school` อีกครั้ง — ทีมต้องยังอยู่**
   (บั๊ก `iso()` เคยทำให้ทีมหายตรงจุดนี้พอดี)
5. `/checkin` — เห็นทีมที่อนุมัติ กดรายงานตัวได้
6. บริจาคทดสอบ 1 บาท — ต้องโผล่ในแท็บบริจาคของแอดมิน

## ถ้าพัง — ย้อนกลับ

### หน้าเว็บพัง แต่ฐานข้อมูลปกติ

เร็วที่สุด: อัป `dist/` ของ build ก่อนหน้าทับกลับไป
**เก็บ `dist/` ของรอบที่ใช้งานได้ไว้เสมอ** อย่าลบทิ้งหลังอัปเสร็จ

ผู้ใช้ที่ติด service worker เก่าให้บอกให้กด refresh —
`index.html` กับ `sw.js` ตั้ง `no-cache` ไว้แล้วจึงได้ของใหม่ในรอบเดียว

### API พัง (500)

1. ดู error log ใน DirectAdmin ก่อน — ข้อความจริงอยู่ตรงนั้น
   API ตั้งใจไม่ส่งรายละเอียดออกไปให้ client
2. อัป `api/` ของรอบก่อนหน้าทับกลับ
3. **ถ้ารัน migration ไปแล้ว การถอยโค้ดอย่างเดียวไม่พอ** ต้อง restore ฐานด้วย
   ไม่งั้นโค้ดเก่าจะเจอคอลัมน์ที่มันไม่รู้จัก

### ฐานข้อมูลพัง

```
phpMyAdmin -> Import -> เลือกไฟล์ kickoff-YYYYMMDD-HHMM.sql.gz
```

Export ที่ติ๊ก `Add DROP TABLE` ไว้จะทับของเดิมให้เอง
**ข้อมูลที่เกิดขึ้นหลังเวลาที่สำรองไว้จะหาย** — ถ้าเป็นช่วงที่โรงเรียนกำลังกรอกรายชื่อ
ต้องแจ้งให้กรอกใหม่ ยิ่งสำรองถี่ยิ่งเสียหายน้อย

**ช่วง 15–31 ส.ค. ควรสำรองวันละครั้ง** เพราะเป็นช่วงที่ข้อมูลเข้ามาเยอะที่สุด
และกู้จากที่อื่นไม่ได้เลย

## ทดสอบก่อนขึ้นทุกครั้ง

```bash
npx tsc --noEmit
npx vite build
```

แล้วรัน smoke test กับ**ฐานทดสอบ** (อย่าชี้ฐานจริง — สคริปต์เขียนข้อมูลลงไป):

```bash
php -S localhost:8788 -t .
php tools/smoke-test.php
```

ยิง API จริงตามลำดับงานจริงตั้งแต่โรงเรียนเข้าระบบจนถึงรายงานตัวหน้างาน
ออกด้วย exit code 1 ถ้ามีข้อไหนไม่ผ่าน วิธีเตรียมฐานทดสอบอยู่ในหัวสคริปต์

ตัวนี้เขียนขึ้นหลังบั๊ก `iso()` หลุดขึ้น production — เป็นบั๊กใน PHP ที่ schema test
จับไม่ได้ และไม่มีใครเคยกด "ดูทีมหลังยืนยันสลิป" ตอนทดสอบด้วยมือ
